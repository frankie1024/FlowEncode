# deew 5.1 / 3.0.0-beta.1 验收

2026-11-12。实现依据 FlowEncode × deew 施工方案 v5。保留既有视觉界面，新增功能性参数、任务中心和接入设置；视觉重设计由用户后续启动。

## 基线与契约

- deew 5.1.0；按最终格式和测量规则选择实际 DEE 6.7.0 工具；truehdd 0.6.2、dee_shim 0.1.0+g294c9d1。
- FFmpeg/FFprobe 9.0.2 stable 精确包；实际子进程解析路径写入日志。
- 支持八种格式参数；`-mo` 只测量、`-k` 保留中间文件、`-kl` 保存诊断。预览显示最终目录，执行使用全新 staging。
- 使用 `DEEW_EVENTS_FILE` 增量读取 UTF-8 JSONL。`done` 不作为成功凭据；退出后等待 stdout/stderr 和事件尾读。媒体成功要求退出码、错误事件和本次新媒体共同通过。
- portable 配置的可写检查、互斥 lease、原始字节恢复、崩溃备份和外部冲突保全均有回归验证。已有错误配置不自动重置。

## 真实短样本

只截取用户素材的 8–20 秒片段，未处理多 GB 全片。5.1 DTS-HD MA 原始片段、由其生成的 7.1/7.0 FLAC、DTS:X 原始短片段共执行 **17 个真实 deew 任务**，全部完成。覆盖普通 DDP、6 声道 bluray 归一化、指定 dialnorm、只测量、DD、AAC、TrueHD、AC4，以及 7.1/7.0/DTS:X 的 standard、bluray/keep-temp、测量组合。

全部媒体使用 FFprobe 核对 codec，`.ec3/.eb3` 跟随有效 profile。AC4 测量响度 -15 dB 与指定 dialnorm -27 dB 分开记录；只测量不生成媒体。每次运行后配置逐字节恢复。HTML/文本日志和保留目录按任务 ID 分离。

本地证据：`artifacts/validation-3.0/deew-layouts/results.json` 与同目录日志、探测 JSON；生命周期、尾读错误、空输出、旧文件、取消/Abort、130 退出、轨道选择、缺配置、错误配置等由实际子进程测试桩覆盖。

## MCP 与桌面

官方 MCP SDK stdio 初始化和 16 个工具 schema 通过；真实 deew 音频和 x264 视频计划 → 提交 → 完成 → 产物流程通过。已验证重复提交、断连后继续、重连查询、按旧 ID 取消不影响新任务、取消后新 ID 重试及重试键去重。16 个并发管道客户端争用同一输出时仅一个获接收。任务历史和幂等收据在桌面重启后保留。

桌面实际检查确认 MCP 任务在任务中心可见；手动音频源探测、参数、执行按钮状态及结果区经过操作。Debug/Release 均进行构建校验。普通回归 **497 / 497 通过**。原始便携 ZIP 解压到普通权限目录后，Release 桌面启动、版本 3.0.0-beta.1 和打包的 MCP EXE 管道连接通过。再使用这份包的 MCP EXE 完成 16 工具初始化、真实音频/视频、幂等重复提交、断连重连、按 ID 取消和重试全流程，全部通过。测试后原用户设置按字节恢复。开发工作区 artifacts 目录带特殊继承权限，不能把该目录内的启动异常当作正常安装目录结果；发布包验收使用原始 ZIP 的独立解压目录。

## Beta 边界

缺少真正的 TrueHD Atmos 测试片段，Atmos 三类输出只有参数/布局/依赖契约验证，**不宣称已通过真实 Atmos 编码验收**。完整蓝光解复用、Av1an 全流程、长片、复杂 HDR/DV/VFR/GPU 脚本、安装器升级回滚矩阵仍待更大样本验证。普通视频产物不自动包含源音轨/字幕。

原有可用 Python 3.12 环境和工具固定路径保留；新安装基线和精确依赖见 [兼容性报告](TOOLCHAIN-COMPATIBILITY-3.0.md)。不随应用分发授权 DEE 组件。
